# 反馈策略与覆盖度实验矩阵

日期：2026-10-21。本文是待实施的实验设计，不是新实验结果；本次仅整理文档，没有修改运行时策略或启动 VM。
历史证据、一手来源及其阅读范围见 [调研](README.md)，资源模板的源码复核见 [前缀复核](PREFIX-REASSESSMENT.md)。

## 1. 实验要分别决定什么

1. **反馈**：什么行为值得入库？候选为 PC、控制流边、公式点、规范化语义状态/转移。
2. **调度**：选哪个父种子，分配多少次变异，给哪些任务预算？
3. **评价**：用同一套独立统计判断探索是否改善，不能只看某策略给自己的奖励分。

已有证据只支持：旧父种子选择实际发生饥饿；固定模板混合负载有更高转换密度；联合反馈和调度收益尚未得到隔离验证。
这些问题不支持直接决定删除全部资源准备，也不支持沿用固定 50% 模板比例。

## 2. 按依赖顺序执行的实验

| 编号 | 要回答的问题 | 对照或操作 | 主要指标 | 决策与启发来源 |
| --- | --- | --- | --- | --- |
| E0 计量校准 | 收到的覆盖/状态信号是否可信、可重放、可归因？ | 固定程序从同一镜像/检查点重复执行；分别观察准备、被测调用、快照、清理；测试多程序、丢事件与对象 ID 改变 | 信号稳定率、归因比例、trace loss、测量/重放成本 | 未通过先修计量；参考 syzkaller triage 和 Linux KCOV |
| E1 可工作基线 | 排除父种子饥饿后，简单选择能做到什么？ | 旧选择只作缺陷诊断；修复后均匀轮转作正式基线。固定反馈、模板比例与任务比例 | 实际父种子分布、等待时间、稳定目标覆盖曲线 | 先离线回归，再单 VM 短测；参考 syzkaller corpus，轮转是我们的可审计基线 |
| E2 前缀消融 | 资源准备帮助了探索，还是固定模板自身制造了命中？ | 普通生成；最小资源准备 + 随机操作；完整模板 + 随机尾部；模板单独执行（诊断臂） | 总覆盖/总耗时；准备、模板、尾部各自的转换及可归因新特征 | 决定模板去留和使用方式；受 syzkaller 资源建模、Janus 状态输入启发，四臂设计是我们的消融 |
| E3 反馈消融 | 哪种反馈比 PC 更有价值？ | 第一批：PC、edge、PC + 公式点、PC + 语义状态；需要确认交互时补 edge + 点、edge + 状态 | 共同评价器的稳定 PC/边、适用公式点、语义状态/转移、额外耗时 | 单独判断 edge、点、状态的收益；参考 syzkaller、AFL++、StateFuzz |
| E4 种子与能量 | 稀有度和动态变异预算是否各自有效？ | 选择方式 {均匀、稀有度加权} × 能量 {固定、动态}，形成四臂；反馈和任务比例固定 | 单位全流程时间的稳定新特征、子代收益、成本、长尾等待 | 不能只比旧的失效选择；参考 AFLFast、libFuzzer/Entropic |
| E5 任务调度 | 根据收益调整任务比例值得吗？ | 任务集合相同：固定比例 vs 自适应比例；种子策略、反馈和场景集合相同 | 覆盖曲线/AUC、各任务真实预算、收益/成本、慢场景遗漏 | 在 E0–E4 后验证；参考 SyzVegas |

E1 的共同测量和记录先统一部署到比较双方；去重、重放过滤等若改变准入逻辑，也必须统一或另设消融。
旧策略的离线复现与运行诊断不作为复杂算法有效性的正式对照。

### E0：先校准，不先调权重

- 用可解释的正常操作、预期失败/回滚和重复相同状态校准观察器；测试夹具或人工注入异常只用于检查检出能力，不能算自然发现的漏洞。
- 分别判断代码通道和语义通道的证据质量，不能拿 checker 总体 `passed` 代替完整性门槛：真实错误本身可能令 checker 不通过。
- 准备、快照、清理和未知后台事件保留在观察报告；没有因果证据不能给当前程序奖励。稳定态异常通过同起点受控重放归因。
- 重放单元包含构建/config、镜像及挂载特性、检查点或状态构建程序、被测程序、runtime fd 修复版本、worker/scenario。
- KCOV task-local 与异步覆盖边界单独标注。旧 program KCOV 数组缺少 syscall 分界，不能直接连接全部相邻 PC 当作真实边。
- 固定 corpus 重放用于定位测量/特征差异；它不能代替在线 fuzzing 的覆盖效率对照。

### E1：先证明父种子确实有机会被变异

历史记录中 1,847 次变异只使用一个父程序，已有审计结果，无须为确认这个事实再跑长测。
先决定本轮任务，只有实际执行变异时才推进父种子选择，避免被丢弃的选择与任务周期互相影响。
固定种子池下轮转应在完整轮次覆盖所有可选种子；动态入库时另记等待时间。
之后若加入均匀随机对照，记录 PRNG seed 与实际选择，不能用轮转的逐轮全覆盖条件要求随机抽样。

### E2：前缀的总收益和随机部分收益都要报告

四臂使用共同环境和相同程序调用上限；以相同全流程时间比较实际效率，准备和模板耗时不能免费。
另作相同随机操作暴露量的诊断，解释短尾部是否仅因调用机会更少而吃亏。
模板单独执行用于解释固定贡献，不当作与随机 fuzzer 等价的探索算法。
可归因代码覆盖需逐调用边界或受控执行证据，不能仅通过两个最终 PC 集合相减宣布因果贡献。

若最小准备改善随机探索而完整模板只增加固定转换，可选择最小准备；若完整程序经普通变异仍有持续收益，可作为初始种子。
“模板作为种子一次入库并允许全程序变异”是后续额外对照，不能仅凭四臂结果宣布已证实。
前缀占比应在后续单独调参后冻结复核，不能默认维持 50%，也不能同时改前缀和反馈再归因于某一个机制。

### E3：反馈和评价器分开

所有实验臂都采集同版本 PC、逐调用边和语义事件；只有用于准入的特征不同。
先使用固定父种子选择、固定每次变异预算和固定任务比例，避免调度同时变化。
PC 与 edge 的比较不同时新增语义反馈；PC + 点与 PC + 状态使用同一 PC 基线。
完整六臂形成 {PC, edge} × {无语义, 公式点, 语义状态}，资源有限时先做四臂，再按结果补交互对照。

规范化状态候选为 `(formula, point, profile, object_kind, phase, gap_bucket, outcome, recovery)`。
状态和转移都要求可信生命周期证据；不奖励原始 inode/block/地址等实例值，不能跨丢失事件构造新转移。
先冻结状态定义及其版本；不能因为某臂启用了状态反馈，就只给它统计状态覆盖。
入库新颖性可先采用集合去重，避免同时引入未经校准的异质奖励系数。
如果只看到自身状态计数增加，而共同的状态转移、目标代码或确认异常没有改善，应收窄结论，并检查状态定义是否膨胀。

### E4、E5：先知道奖励可信，再试复杂调度

稀有度按“多少次执行命中过该特征”统计，每次执行对同一特征最多记一次；不采用 raw trace hit 总数。
动态能量保存实际变异次数、子代新增稳定特征与总成本，避免只按入库时的发现量永久评分。
选择和能量做四臂，是为了分别估计“选谁”和“多变异几次”的效果。
调参数据与最终验证的随机种子分开；参数冻结后复核，不能挑最好权重当结论。

E5 仅改变任务预算分配，不能顺便增加新的镜像/场景。
Janus 启发的镜像/场景扩展另立实验：固定调度和反馈、固定总预算，比较既有场景与扩展场景，并报告各场景共同评价范围。
不能只因增加了镜像类型，就把新增适用点算作调度算法提升。恢复/压力等慢场景的预算与遗漏需要单独报告。

## 3. 共同评价口径

| 指标 | 报告方式 |
| --- | --- |
| 代码覆盖 | 固定构建，按源码范围区分 ext4、jbd2、checker；稳定唯一 PC 与边分列，提供随时间曲线与 AUC |
| 百分比覆盖率 | 只有分子分母口径一致、固定插桩点/源码行清单时才报告；不能拿 PC 数除以源码行数；无可靠边分母时只报边数 |
| 公式点覆盖 | 按镜像/挂载/scenario 列适用点清单、已命中点及未命中点，标注不适用原因 |
| 状态覆盖 | 同版本规范化状态与转移数量；未知完整状态空间时不编造百分比 |
| 调用转换密度 | 按准备、模板、随机部分分别统计，只作负载诊断，不能替代探索效果 |
| 反馈质量与调度 | 信号稳定率、完整性、归因比例；父种子分布、未选择种子及等待时间 |
| 成本与错误 | 全流程时间及分项；重放确认的独立异常、首次发现时间；没有确认漏洞如实报告 0 |

覆盖主指标、最小有意义收益与可接受开销在正式比较前声明；看完整曲线，避免只挑有利时间点。
除全流程时间外，提供等已核验 syscall 预算作为诊断；生成、编译、传输、分析、快照、triage/重放都计时。
采用相同硬件/并发上限、内核/checker/allowlist 与资源约束，独立重置各轮初始状态；不同文件系统特性分层报告。
各臂先安排相同数量的独立随机种子 pilot，例如 5 个起步；这不是充分样本数的保证。
根据 pilot 的方差、开销和可识别效应确定正式重复数和预算；运行顺序随机化或分块，报告中位数、离散程度及不确定性。
固定 corpus 诊断、调参和最终验证分开；在线实验允许 corpus 演化，但起始 corpus 和重放环境相同。

## 4. 我们具体从哪些工具得到启发

| 来源 | 借鉴内容 | 不应声称的内容 |
| --- | --- | --- |
| syzkaller | 类型化 syscall/资源关系；signal 与 cover 分开；triage/deflake、最小化、corpus 管理 | 当前调用 Generate/Mutate 等于已有完整 manager 闭环；均匀轮转来自其默认调度 |
| AFL++ / AFLFast | 边覆盖、按执行频率看稀有路径、按观测分配变异能量 | 直接套一个 `rare` 或固定倍数就能提高本项目覆盖 |
| libFuzzer / Entropic | 特征频率、变异次数、动态能量及执行成本统计 | 直接移植字节流变异器就能处理 syscall 资源图 |
| StateFuzz | 状态值及语义转移补充代码覆盖 | 原论文已有我们的 ext4 公式状态方案 |
| SyzVegas | 基于观测收益调整任务和种子选择 | 套用 bandit 能修复污染的奖励或自动获得论文增益 |
| Janus | 镜像状态与 syscall 序列共同构成输入和重放上下文 | 当前固定资源模板就是 Janus 算法；旧 LKL 实现可直接接当前 VM |
| Linux KCOV | 代码覆盖采集及 task/remote 边界 | KCOV 本身提供语义反馈、漏洞判定或调度算法 |

以上为可验证的设计来源；我们的公式规范化、前缀四臂消融和具体基线是本项目设计。
源码、官方文档、论文/作者页面及实际阅读范围统一见 [调研一手来源](README.md#9-一手来源与阅读范围)。

## 5. 第一批实际工作

1. 统一输出程序/调用级来源、逐调用 KCOV 边界、成本、父种子实际选择和重放上下文；完成 E0 的离线/短测验收。
2. 修复父种子选择并建立 E1 简单基线；只做必要短测，先确认没有饥饿与归因污染。
3. 实施 E2 前缀消融，再在固定输入策略下做 E3 反馈对照。
4. 只有 E3 的独立重复实验支持新增信号，才继续 E4、E5；不支持时保留简单方案并记录结果。

每个实验交付一份配置清单、原始证据、统一评价报告和明确结论；当前文件不表示这些运行已经完成。
